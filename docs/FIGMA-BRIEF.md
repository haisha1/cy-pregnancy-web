## 1. 可直接使用的主提示词

> 为“春雨孕算”设计桌面管理 Web。它与既有 App 是同一产品，必须继承 App 的视觉系统，不能重新创作另一套医疗后台风格。
>
> 使用 App 的蓝青渐变、浅蓝/浅青/极淡粉柔光背景、24px圆角玻璃卡片、12px输入圆角、16px按钮圆角、系统中文无衬线字体和同风格线性图标。主色 Light #2F6BFF、Dark #79A4FF；品牌卡 Light #2F6BFF→#34C9B8，Dark #4E86FF→#46D6C4。主要按钮使用更深的 #285CEC→#087D72 并验收白字对比。完整颜色、透明度和深色值以 DESIGN.md 为准，不自行近似取色。
>
> 页面背景 Light #EAF2FF→#E6F7F4→#FFF0F6，Dark #0B1020→#111C38→#16132E。普通玻璃卡用于外层，长文、表格、字段与浮层使用 strong 面；玻璃不妨碍文字阅读。只在背景、品牌区和一张工作台重点卡表现品牌，普通数据区保持稳定高对比。不要每个区块都做大渐变。
>
> 设计1440×900桌面主画板：232px侧栏、64px顶栏、24px页面边距、16px区块间距、40px标准控件、52px表格行。导航是圆角玻璃面，表格是完整的strong工作面。不要照搬手机底部tab、微信胶囊或390px窄内容区。1280×720、1920×1080补响应式；<1024侧栏变抽屉，审核双栏变纵排。
>
> 核心任务为登录、知识列表、创建/编辑双表达、版本详情、独立审核、管理库发布、账号与审计。专业和白话是同一内容版本的两个可见编辑/阅读面板，不是后台全局模式开关。正文使用纯文本，不做富文本假按钮。
>
> 先建立Theme Light/Dark变量和共享组件，完成登录、知识列表、知识编辑、审核详情四类代表页面，经同风格对照后再展开全部18个计划页面。复用组件实例，不把整页做成图片或手工复制独立样式。
>
> 数据必须区分真实接口能力与设计示例。已有目录只支持游标上一批/下一批，没有总页数、全库搜索或全量审核/发布队列。后续增强状态单独标注“接口待补”，不要把当前页筛选当全库筛选。工作台无统计接口时展示任务入口与能力，不填假运营数。管理库已发布不等于App已生效。系统能力不等于数据库/Redis当前健康。
>
> 所有代表页同时完成Light/Dark，以及加载、空、无结果（接口支持时）、失败、未接入、403、会话过期、校验、409冲突、busy和成功状态。控件展开态、焦点、禁用、弹层回焦和减少动态要覆盖。错误保留输入，状态必须有文字。
>
> 禁止沿用旧版#167C80青绿主色、珊瑚强调、低圆角仪器面板、“监护台”隐喻、“孕周轴”、心电图、黑底霓虹大屏或组件库默认皮肤。不要把App的柔光粉色扩大为母婴营销风，也不要完全移除玻璃材质导致再次不像同一产品。

## 2. 原型来源与对照方法

- 已有 Figma [Foundations](https://www.figma.com/design/v2qVMT75ALDDAhMiKboLlD?node-id=0%3A1)、[Components](https://www.figma.com/design/v2qVMT75ALDDAhMiKboLlD?node-id=4%3A2)，功能索引见 [PRD 设计交付](../../docs/prd/06-设计交付与追踪.md)。这些链接继承现有交付记录，本次没有重新读取远程节点。
- App 运行主题与 App DESIGN 是颜色和实现差异依据；早期截图只可对照材质，不能把过时入口/待开放状态当最新业务。
- 每次评审并排放 App 当前工具/我的页面与 Web 列表/审核页面，比较蓝青、柔光、圆角、卡面、图标、按钮和文字层次。
- 色彩一致不意味着复制手机布局；管理端加表格和双栏，但这些元素也必须由同一材质和尺寸层级派生。

## 3. 建议 Figma 分区与命名

| 分区                  | 交付内容                                                  |
| --------------------- | --------------------------------------------------------- |
| Web-00-Foundations    | 品牌、共享/桌面令牌、主题映射、材质/降级、对比样本        |
| Web-01-Components     | Shell/Card/Button/Field/Select/Table/Dialog/State等组件集 |
| Web-02-Content        | W05-W08，双表达、来源、版本                               |
| Web-03-Review-Release | W09-W11，注明A/B阶段和管理库边界                          |
| Web-04-Account-System | W01/W12-W18，鉴权、账号、预置角色、审计、能力             |
| Web-05-Overview-Users | W02-W04，统计和用户查询标接口依赖                         |
| Web-06-States         | 加载/空/失败/冲突/权限/确认/离线/主题降级                 |
| Web-99-Handoff        | W编号、路由、组件、DTO与能力映射、未决事项                |

画板命名示例：`Web/W05/Light/Default`、`Web/W07/Dark/Conflict`。路由数量不是画板数量：18个计划页面的双主题默认态为36个基准画板，附加状态与响应式另计；不强迫未实现接口伪造真实内容。

组件名称采用 Cy 前缀，variant 轴至少区分 Theme、State、Size，业务组件再加 ReadOnly/Edit 等轴。背景、文字、语义色绑定 Theme，不在每个实例硬编码。

## 4. 首批四页的审查重点

| 页面     | 风格/业务检查                                                         |
| -------- | --------------------------------------------------------------------- |
| W01 登录 | 品牌与表单玻璃统一；无假实时数字；密码错误与限流可读                  |
| W05 列表 | 24px整体工作面，52px行；游标分页；当前发布标识与state区分             |
| W07 编辑 | strong双栏、引用依据、稳定错误区；长文不跨屏；保存不等于送审          |
| W10 审核 | 完整双表达与来源，意见保留，禁止自审；没有submittedAt就不伪造提交时间 |

这四页中任意一页仍像独立的青绿仪器后台，应先修组件/令牌，再批量扩展页面。不要通过给首页加一个蓝色角标掩盖全站风格漂移。

## 5. 交付物

可编辑组件与画板、变量映射、双主题截图、关键流程原型连接、展开/失败状态、响应式变换、W编号覆盖表，以及“已设计/待接口/待确认”清单。没有后端能力的页面可以交付完整方案，但必须明确其示例性质和上线依赖。
